# FORGE INDIA — OPERATING VISION

**Status:** Current operating direction for FORGE WORLD

**Decision date:** 2026-08-25

**Relationship to the existing North Star:** This document does **not** delete or replace the long-term FORGE WORLD ambition. It narrows the current operating scope so that FORGE can become much deeper, more useful, and more publicly releasable faster. The long-term universal/global vision remains intact; the present build target is India-first.

---

## 1. The decision

FORGE WORLD now has a focused operating objective:

> **FORGE INDIA: Given any physically meaningful industrial objective, determine whether India can build it, what India already possesses, what is missing, what must be imported, what can be localized, what can be substituted or redesigned, what capabilities and infrastructure must be created, how shocks alter the answer, and what sequence of actions can make the objective achievable.**

India is now the center of the solve.

The rest of the world remains highly relevant, but primarily as India's external industrial environment: suppliers, technologies, materials, minerals, capital equipment, logistics routes, export-control jurisdictions, strategic dependencies, alternative sources, competing demand, geopolitical risks, and substitution options.

FORGE should not spend its present data-expansion effort trying to model the complete independent industrial capability of every country. Questions such as "Can Brazil build this?" or "Can Europe build this?" are deferred unless they are directly relevant to India's sourcing, dependency, competition, or resilience.

## 3. The product starts with an objective, not a capability database

The public-facing experience should begin with a meaningful question:

> **Can India build this?**

Examples:

- Can India manufacture an MRI machine domestically?
- Can India manufacture 1 million humanoid robots per year?
- Can India build 10,000 satellites per year?
- Can India manufacture advanced 5-axis CNC systems?
- Can India build a modern passenger aircraft supply chain?
- Can India produce 100 GW/year of electrolyzers?
- Can India manufacture high-end industrial robots without Chinese rare-earth magnets?
- Can India build a nuclear fleet at a specified annual rate?
- Can India localize a complete semiconductor-equipment chain?
- Can India manufacture agricultural drones at very large scale?

The user should not need to know obscure industrial terminology before asking the question.

FORGE must translate the objective into the underlying industrial reality.

---

## 4. Complete decomposition is mandatory

FORGE must decompose the **entire product/system**, not only the parts India lacks.

The general structure is:

```text
OBJECTIVE / PRODUCT
    -> architecture
    -> major systems
    -> subsystems
    -> assemblies
    -> components
    -> subcomponents
    -> functional requirements
    -> materials / grades / chemicals
    -> manufacturing processes
    -> machines / equipment
    -> tooling / fixtures / dies / molds
    -> metrology / testing
    -> qualification / standards
    -> workforce / know-how
    -> organizations / facilities
    -> capacity / allocation
    -> geography / logistics
    -> upstream dependencies
    -> evidence / unknowns / conflicts
```

A product may require hundreds or thousands of underlying requirements. FORGE should retain that depth.

However, the user interface should not dump all of it onto a normal user at once.

---

## 5. Plain-language decision layer, expert-depth underneath

The product must work at two levels simultaneously.

### Front layer

A normal user should quickly understand:

- what India can already make;
- what India can make but not at the required specification or scale;
- what is import-dependent;
- what is genuinely missing;
- what remains UNKNOWN;
- the small number of bottlenecks that actually determine the answer;
- what India could realistically localize;
- what India should build first;
- which capabilities unlock multiple downstream industries.

### Deep layer

An expert should be able to drill from a bottleneck all the way to:

```text
subsystem
-> component
-> exact functional requirement
-> specification/tolerance/performance envelope
-> material grade
-> process route
-> machine
-> tooling
-> metrology
-> qualification
-> candidate Indian supplier/facility
-> demonstrated maturity
-> capacity evidence
-> source
```

The obscure spring, seal, bearing, pump or coating matters because of the parent system it enables. FORGE should explain that context before expecting the user to care about the primitive itself.

---

## 6. India-status overlay

Once the full product dependency tree exists, FORGE overlays India onto every decision-relevant requirement.

Useful states include:

- **STRONG / AVAILABLE IN INDIA** — evidenced domestic capability plausibly meets the requirement;
- **PARTIAL / SCALE-LIMITED** — related capability exists but scale, yield, quality, allocation or maturity may be insufficient;
- **SPECIFICATION GAP** — India can make the general class but not the required performance envelope or qualification;
- **IMPORT-DEPENDENT** — requirement is currently met substantially through foreign supply;
- **MISSING / NO EVIDENCED DOMESTIC CAPABILITY** — evidence supports a genuine domestic gap;
- **UNKNOWN** — public evidence is insufficient;
- **CONFLICTED** — credible evidence disagrees.

UNKNOWN must never be presented as MISSING.

A lack of evidence is not proof of incapability.

---

## 7. Localization is not a binary make-or-import decision

When India cannot make an exact requirement, FORGE must explore a portfolio of paths.

```text
EXACT REQUIREMENT UNAVAILABLE
        |
        +-> IMPORT
        +-> DIVERSIFY IMPORT SOURCES
        +-> LICENSE / TECHNOLOGY TRANSFER
        +-> BUILD EXACT CAPABILITY DOMESTICALLY
        +-> SUBSTITUTE MATERIAL / COMPONENT / PROCESS
        +-> USE AN ADJACENT INDIAN CAPABILITY
        +-> REDESIGN THE PARENT ARCHITECTURE
        +-> ACCEPT TEMPORARY IMPORT DEPENDENCE WHILE LOCALIZING
        +-> DEVELOP A NEW INDIGENOUS TECHNOLOGY ROUTE
```

Substitution is not merely changing one supplier to another. It may require a graph rewrite and a full re-solve.

Example: if an architecture depends on a rare-earth permanent-magnet motor that creates an unacceptable foreign dependency, FORGE should be able to compare alternative motor/actuation architectures, changed gearing, thermal trade-offs, altered performance targets, different power electronics, or alternative materials, then recompute the entire objective.

DESIGN therefore remains a core capability of FORGE INDIA.

## 10. IndiaBUILD is a minimum coverage benchmark, not the architecture

FORGE INDIA should account for the publicly accessible IndiaBUILD capability universe as a minimum breadth benchmark.

FORGE should aim to know at least the useful public capability, builder, maturity, dependency, policy, gap and evidence information represented there, while preserving source attribution and independent epistemic review.

IndiaBUILD must **not** become numerical authority merely because it is a useful benchmark.

FORGE should materially exceed a flat capability catalogue by connecting capability records to:

- complete product decompositions;
- processes;
- machines;
- tooling;
- metrology;
- materials;
- qualifications;
- facilities;
- capacity;
- geography;
- imports;
- supplier states;
- substitutions;
- redesign options;
- shocks;
- transformation paths;
- proof/evidence.

The objective is not "FORGE has a larger count." The objective is "FORGE can answer deeper buildability questions using a broader and more causally connected industrial model."

No useful global research should be deleted because of the India-first pivot.

Existing and future evidence about China, Japan, South Korea, Taiwan, Germany, the United States, Russia, Australia, Europe and other geographies remains valuable whenever it affects India.

The global layer should retain information relevant to:

- foreign manufacturers and suppliers;
- strategic commodities and minerals;
- upstream processing;
- machine tools and production equipment;
- semiconductors and electronics;
- advanced materials;
- technology/IP/licensing;

- sanctions and restrictions;

- commodity and freight exposure;

The model should therefore be thought of as:

```text
DEEP INDIA CORE
    +
SELECTIVE GLOBAL DEPENDENCY / SOURCING / RISK LAYER
```

rather than a shallow encyclopedia of every country.

## 12. Shocks and resilience remain first-class

FORGE INDIA must answer not only:

> Can India build it under the baseline world?

but also:

> Can India still build it when the world becomes hostile, expensive, constrained or disrupted?

Relevant shock families include, where evidence and data permit:

- war and geopolitical conflict;
- sanctions;
- export controls;
- supplier-country restrictions;
- rare-earth/material restrictions;
- semiconductor disruption;
- oil-price shocks;
- natural-gas/energy-price shocks;
- copper, nickel, lithium and other material-price shocks;
- freight-rate spikes;
- shipping-corridor disruption;
- port/corridor closure;
- exchange-rate movement;
- loss of a critical capital-equipment supplier;
- sudden competing demand for scarce machine/equipment/material capacity;
- delayed projects and qualification failures.

A shock should alter real constraints and trigger a re-solve, not merely add a red risk score.

The result should show which Indian objectives fail first, why, and which substitution/localization path increases resilience.

## 13. Evidence and epistemic integrity remain constitutional

FORGE INDIA must continue to distinguish:

- MEASURED
- REPORTED
- DERIVED
- ESTIMATED
- MODELLED
- ASSUMPTION
- SCENARIO
- UNKNOWN
- CONFLICTED

Hard rules remain:

- UNKNOWN != zero
- import eligibility != supply
- trade != production capability
- facility existence != qualified capability
- company existence != supplier qualification
- nameplate != effective capacity
- effective capacity != available allocation
- project announcement != operating production
- mineral reserve != processed usable material
- known manufacturer != qualified supplier
- qualified supplier != available allocation
- patent != industrial capability
- LLM output != numerical authority

A strong public FORGE product should make uncertainty visible rather than hide it.

Every consequential conclusion should be inspectable through:

```text
verdict
-> bottleneck
-> dependency
-> entity
-> claim
-> evidence
-> source
```

- Qualification
- Facilities

- Geography

## 15. What "100% FORGE India" means

The India-first V1 target does **not** mean omniscient knowledge of every factory, spring or machine in India.

A strong V1 means:

- the architecture is general;
- IndiaBUILD-level breadth is accounted for;
- the major physical industrial economy is broadly represented;
- high-value foundational capabilities are deeply connected;
- arbitrary objectives can compose substantial dependency trees from reusable primitives;
- India status is evidence-bounded;
- imports and foreign dependencies are visible;
- localization and alternative architectures can be explored;
- shocks can be re-solved;
- important UNKNOWNs generate research tasks;
- normal users can understand the answer;
- experts can inspect the detailed engineering/evidence layer;
- the system is good enough to expose publicly without pretending to know what it does not know.

FORGE can continue expanding forever after that point.

## 16. Immediate build priority

The current priority order is:

1. preserve and integrate the existing FORGE reasoning engine;
2. make the India-first operating scope explicit;
3. inject the existing Manus and GLM research into a reusable evidence-backed world model;
4. achieve and then exceed IndiaBUILD breadth;
5. construct an all-sector India capability census;
6. connect reusable processes, machines, materials, metrology, workforce and qualifications across sectors;
7. deepen Indian organizations, facilities, geography and capacity where evidence supports them;
8. retain relevant global supplier/dependency/risk evidence;
9. strengthen arbitrary-product decomposition and India-status overlays;
10. strengthen localization, substitution and architecture-redesign paths;
11. benchmark the system across very different Indian objectives;
12. present the results through a public-quality objective-first product experience.

Global country-by-country buildability expansion comes later, after FORGE INDIA is strong.

---

## 17. Final operating principle

FORGE INDIA should not become an industrial Wikipedia.

It should become a **computational model of what India can build, why, what it cannot yet build, what it depends on, and what changes would make new physical futures possible.**

The deep graph exists to answer human questions, not to impress users with graph size.

The front of the product should say:

> **What do you want India to build?**

The system underneath should be capable of answering with the full industrial reality it can defend.
